# v0.5.0 — Operational core

Inventory stops being a list you can only read and becomes one you can work.

## Find anything

Current Inventory is paged, sorted and filtered by the database over the whole
workspace. Previously it fetched at most 100 rows and asked you to narrow the
search; sorting reordered whichever rows had already loaded, so "newest first"
meant "newest of the hundred that arrived".

- Previous/Next, a visible range and an exact total
- 25 / 50 / 100 per page
- ten sort orders, including quantity, location, condition and recently moved
- filters for category, vertical, location, grader, tracking mode, photos,
  location gaps, missing condition details, recency and a date-added range
- the whole query lives in the URL, so a filtered view can be bookmarked or
  sent to someone and the Back button restores the page you were on

Individual units and quantity lots are paged together as one stream. Serialized
parent lots are excluded so the same physical stock is never counted twice.

## Know what something is

Intake always asked whether a thing was Apparel or Electronics. Everything after
commit saw only the broad "other" vertical, so that answer was collected and
thrown away.

Records now carry an exact category — Graded Card, Raw Card, Sealed TCG,
Footwear, Apparel, Electronics, Other Collectible — derived from facts already
stored and frozen once written. Where the stored facts do not identify one, the
record is marked Unclassified for review rather than guessed at.

## Search what you actually know

Search reaches set name, card number, language, printing, grade, certificate,
serial, brand, silhouette, style code, colorway, size, box status, model,
category and location — not just the display name. Scanning an exact identifier
surfaces that record on its own, above the substring matches.

## Move several things at once

"Move" on a selection used to open the first selected record. It now moves all
of them: one governed movement event each, a per-record result, and retry
offered for the failures alone. Records that moved stay moved when a later one
fails.

## Control quantity

Quantity was frozen at commit and had nowhere to go.

- **Adjust** for a stated reason: received, recount, damaged, lost, stolen,
  donated, internal use, returned to supplier, sold elsewhere, other
- **Recount** takes the number you counted and works out the difference itself
- **Split** moves part of a lot to another location as a new lot of the same
  SKU, conserving units exactly
- **Merge** folds compatible lots together — same SKU, same location, both
  active — and refuses on a matching name alone

Every change records who, when, from what, to what, and why. Quantity history is
kept separate from movement history: one answers how many, the other where.

Nothing writes a quantity from the browser. All of it runs through governed
database functions, and each write carries the number you were looking at, so
two people counting the same shelf get a conflict instead of silently
overwriting each other.

Lots absorbed by a merge, or emptied to zero, are never deleted — their history
stays readable — but they stop counting as available stock and cannot be moved.
